# 项目框定：GlobMeet 国际智能会议协同平台

## 1. 项目目标

为跨国家和地区的会议参会人员、会务人员与系统管理员提供一个国际化会议预约与参会协同 Demo，降低多语言沟通、时区换算、日程冲突、信息不同步和多角色协作带来的操作成本。

本项目按研发智能挑战赛的 `competition` 模式推进：以完整、可演示、可复现的业务闭环和高保真移动端体验为优先，不建设生产级基础设施。

## 2. 目标用户与核心情境

| 用户 | 核心情境 | 期望结果 |
| --- | --- | --- |
| 国际参会人员 | 需要以自己的语言和时区查找、预约并按时参加会议 | 获得适合的会议建议、无时区歧义的日程与明确的预约结果 |
| 会务人员 | 需要审核预约、协调冲突，并向参会人员同步会议变更 | 快速完成可追溯的审核、调整和通知 |
| 系统管理员 | 需要维护会议、角色权限与现场核验规则 | 保障角色边界、审计可见性与基础隐私保护 |

## 3. 初始边界

### 必须构成闭环

- 会议查询、预约申请、审核确认、日程管理、变更通知与现场核验。
- 中英双语、跨时区展示、移动端适配。
- AI 驱动的会议推荐与行程安排，且 AI 建议须可解释、可调整、可恢复。
- 参会人员、会务人员、系统管理员三类角色的可见权限与变更追溯。

### 可模拟的部分

- 会议与用户数据使用预置的本地演示数据；预约、审核、变更和核验在浏览器内完成可见状态变化。
- 通知、二维码核验、翻译、时区转换和 AI 推荐/行程能力以可交互的模拟结果呈现。
- 参会入口可模拟跳转或“进入会议”状态。

### 明确不做

- 实时音视频会议、真实日历账户同步、真实消息推送、真实身份认证。
- 服务端持久化、支付、生产级权限体系、实时多人协作和跨设备数据同步。

## 4. 成功信号与交付约束

- 评审可在本地从预约到审核、变更通知、日程更新和现场核验完成一条闭环演示。
- 多语言、跨时区、角色权限、AI 建议与移动端适配均能在可复现状态中直接检查。
- 交付覆盖产品场景分析、产品方案、UX/UI、可交互 HTML Demo、交付说明和 AI 能力说明六个考核维度。
- 代码与演示保持本地可运行、无持续性 JavaScript 报错；真实与模拟能力的边界明确标注。

## 5. T0 决策

- 使用工作名“GlobMeet 国际智能会议协同平台”。
- 产品范围是“会议预约与参会协同”，不包含真实音视频通话能力。
- 决策负责人为用户；当前已确认 T0 范围，下一阶段进入 T1 需求定义。
