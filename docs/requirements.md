# GlobMeet 国际智能会议协同平台 PRD

**版本：** T1 已确认 / T4 信息架构同步待确认  
**产品模式：** 竞赛 Demo，预置本地数据与可交互模拟结果

## 1. 项目背景

### 1.1 问题与机会

跨国会议的参会人员、会务人员与管理员需在不同语言、时区和工作日历下协作。当前预约方式容易产生会议含义误解、时区换算错误、日程撞期、审核进度不透明及变更通知遗漏。GlobMeet 以一个可演示的移动端闭环验证：将会议查询、预约、审核、日程、变更和现场核验统一到同一协同体验中，并用 AI 降低选择和行程安排成本。

### 1.2 产品目标与成功信号

| 目标 | 成功信号 |
| --- | --- |
| 让参会人员完成无歧义预约 | 以本地时区查看会议、提交预约并清楚看到审批结果与下一步。 |
| 让会务人员高效处理申请和变更 | 可从待审列表批准、拒绝或调整申请，并使申请人日程和通知同步更新。 |
| 降低跨国排期成本 | 可切换界面语言和时区，看到等价会议时间；AI 推荐与行程建议可解释、可编辑。 |
| 满足竞赛演示与验收 | 评审可按预置数据重现完整闭环，关键状态和模拟边界清晰可见。 |

### 1.3 约束

- 使用浏览器内预置数据和本地状态，不接入真实账户、日历、通知、翻译或音视频服务。
- 以移动端为主，桌面端保持稳定；所有模拟数据、角色和状态须能在无网络条件下演示。
- 真实与模拟的能力边界须在技术说明和 Demo 内以适当方式说明，且不展示敏感个人数据。

## 2. 范围

### P0 必须完成

- `MEET-01`：会议查询、筛选、详情及本地时区展示。
- `BOOK-01`：预约申请、冲突识别、提交反馈与申请状态。
- `REVIEW-01`：会务审核、批准/拒绝/调整及可追溯处理记录。
- `SCHEDULE-01`：个人日程、时区切换、语言切换、AI 推荐与可编辑行程建议。
- `CHANGE-01`：会议变更、通知中心和参会人日程的同步更新。
- `CHECKIN-01`：预约凭证与会务侧现场核验。
- 三种演示角色：参会人员、会务人员、系统管理员；其页面入口与可操作范围可辨识。

### P1 有余力再做

- 收藏与分享会议、批量导出个人行程。
- 会议等候名单、容量预警与会务运营统计。
- 第三种或更多界面语言、深色模式与无障碍偏好设置。
- 管理员可视化维护会议、场地及语言资源。

### 明确不做

- 实时音视频会议、真实身份认证、真实支付、真实消息推送和真实第三方日历同步。
- 服务端持久化、跨设备同步、实时多人并发协作与生产级审计。
- 未经用户提供或授权的真实个人、行程和证件信息。

## 3. 用户与核心任务

| 用户/角色 | 使用情境 | 核心任务 | 期望结果 |
| --- | --- | --- | --- |
| 国际参会人员 | 在出发前或会议期间，用熟悉的语言和自己的时区安排行程 | 找到会议、查看详情、申请预约、处理冲突、接收变更、出示凭证 | 不误解时间，明确申请进度，有可执行的参会安排 |

### 4.1 页面归属与导航规则

参会人员端一级导航固定为“会议、日程、通知、我的”：会议承载查询、筛选、详情和预约；日程承载本地时区时间线与 AI 行程建议；通知承载审核结果、会议变更和待确认调整；我的默认展示预约状态，并承载凭证、语言、时区和演示角色偏好。会务人员端一级工作区固定为“待办、会议、核验”：待办处理申请，会议发布负责范围内的变更，核验用于现场签到。

- AI、冲突处理、凭证、操作记录、角色切换和系统管理均是对象页、结果页、个人菜单或管理员页面中的二级能力，不得以独立全局一级入口出现。
- “会议”是对外的一级文案；`discover` 可作为运行时内部兼容标识，但不得作为用户可见导航名称或新增功能模块名称。
- 角色切换仅服务竞赛演示，进入“我的 > 偏好与演示角色”；它改变可见工作区，不授予越权操作能力。
- 一级导航重组不改变 REQ-001 至 REQ-016 的规则、数据边界、角色权限或验收结果。

## 7. 非功能要求

- **目标设备与视口：** 以 375 x 812 和 390 x 844 移动视口为优先；在 1440 x 900 桌面视口无溢出、遮挡或不可操作元素。
- **性能与资源：** 预置数据加载后主要页面切换应即时可见；不得依赖外网、远程字体或外部 API 才能完成演示。
- **可访问性：** 可操作元素具有可辨识名称和键盘焦点；文本与背景具备足够对比；颜色不作为状态的唯一表达；中英文文案不截断。
- **安全与隐私：** 仅使用虚构演示数据；凭证展示最少必要字段；无权限操作不改变状态；不在代码或文档中写入密钥。
- **兼容性：** 当前版本 Chrome、Safari 的近期桌面及移动浏览器；现代 `Intl` 时区格式化能力为运行前提。

## 8. 总体验收标准

1. 以“国际参会人员”身份，在中文和上海时区查找一场会议，切换到 English 和 New York 时区后，会议仍指向同一绝对时刻且界面文本已切换。
2. 对存在日程冲突的会议发起预约，看到冲突和替代建议后仍提交；申请在会务人员待审列表出现。
3. 切换到“会务人员”，批准该申请，使参会人员的预约状态、通知、日程与凭证同步变化，并留下操作记录。
4. 会务人员变更已预约会议的时间或地点，参会人通知和日程同步更新；若产生冲突，有可理解的处理入口。
5. 打开已批准预约的核验凭证，在会务侧用同一模拟码完成一次核验；参会人和会务记录均显示已签到，重复核验不重复签到。
6. AI 推荐或行程建议可看到理由，且只有用户明确采纳后才影响日程。
7. 参会人员在所有移动端一级入口中仅看到“会议、日程、通知、我的”；会务人员仅看到“待办、会议、核验”，其余能力在对应对象或个人上下文中进入。
7. 以上流程在目标移动视口和桌面视口均可直接演示，无持续 JavaScript 报错，且无需外部网络服务。
