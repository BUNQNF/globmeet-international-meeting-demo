## 2. 视觉方向

- 核心表达：以日历和任务工作台为灵感的国际会议协同界面。细密的信息结构由圆润浅色卡片承载，让日期、时区、状态和动作形成稳定的扫描路径。
- 参考转译：采用柔和浅灰画布、白色悬浮卡片、`16-20px` 圆角、轻阴影、紫罗兰胶囊导航和紧凑日历密度；当前/选中胶囊为蓝紫线性渐变、柔和紫色投影与低密度白色星点纹理；不复制参考项目的品牌、文案或产品结构。
- 业务语义：紫色仅用于当前状态与主操作；绿色表示已确认/签到，琥珀色表示待审或会议变更，红色仅表示冲突或拒绝。所有状态保留文字，颜色不能成为唯一信号。
- 交互重心：参会人员端以“会议、日程、通知、我的”组织连续任务，其中冲突决策、AI 建议和凭证在对应上下文出现；会务端以“待办、会议、核验”组织高频工作。
- 应避免的表现：深色科技风、强渐变、玻璃拟态、把风险提示做成无语义的装饰色块、在移动端以悬浮控件遮挡日程内容。

## 5. 设计令牌

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `color/bg/canvas` | `#F7F7FB` | 浅灰紫画布 |
| `color/surface/base` | `#FFFFFF` | 顶部栏、会议卡、队列和面板 |
| `color/surface/soft` | `#EEE9FF` | 胶囊轨道、日期方块、非阻断状态面 |
| `color/text/primary` | `#1C1B2A` | 标题和关键内容 |
| `color/text/secondary` | `#78758D` | 元数据与解释文本 |
| `color/action/primary` | `#7758E8` | 主操作、当前导航、AI 行动面 |
| `color/status/success` | `#23A36D` | 已确认、已签到 |
| `color/status/pending` | `#D98A30` | 待审核、会议变更 |
| `color/status/danger` | `#D94F5E` | 冲突、拒绝 |
| `color/border/default` | `#EAE8F2` | 卡片和次操作描边 |

- 字体：中文界面为 `Noto Sans SC`，英文会议名、时间及数据标签为 `Inter`。
- 字阶：页面标题 `25-28/34-38`，区块标题 `18-22/26-30`，卡片标题 `14-16/20-22`，正文 `12-14/18-20`。
- 表面：卡片圆角 `16-20px`；仅白卡使用低不透明度、`y=6-7px` 的柔和阴影，避免层层投影。
- 选中态：蓝紫线性渐变（亮薰衣草至主紫），白色文字，`y=6px` 紫色柔影，点状纹理不超过控件面积的 `10%`；仅用于可切换的当前筛选、日期和导航项，不用于提交/批准等主操作。
- 主操作：靛蓝至紫色线性渐变（`#493CBA` 至 `#8066E6`），白色文字，`y=6px` 靛紫柔影；用于预约、提交审核、采纳替代场次和批准同步，不使用星点纹理。
- 会议主题卡：保持白色内容面，可使用薰衣草至天蓝、珊瑚至暖黄的 `1.5px` 内描边；不使用渐变填充、玻璃内层或额外投影。渐变仅表达会议类别或时间块，不得表达成功、变更、冲突或审核结果。

## 6. 静态与动态资源边界

| 元素 | 实现方式 | 动态内容 | 说明 |
| --- | --- | --- | --- |
| 会议、申请、容量、时区、状态 | DOM + 本地模拟数据 | 是 | 根据当前语言和时区展示；不调用外部会议系统。 |
| AI 建议与理由 | DOM + 本地规则 | 是 | 触发条件、理由和采纳结果均可见；采纳前不写入日程。 |
| 审核、通知和变更记录 | DOM + 本地事件数据 | 是 | 保留可追溯状态，展示同步影响。 |
| 核验码 | DOM 文本 | 是 | 演示 ID，不使用真实二维码或扫码服务。 |
| 图标与装饰媒体 | Lucide SVG / 不使用图片 | 否 | 不依赖位图或外部图片；信息与状态本身构成视觉主体。 |

## 7. 响应式与安全区

- 移动基准：`390 x 844`，左右边距 `18px`，顶部栏 `72px`，底部导航固定且不覆盖滚动内容。
- 桌面基准：`1440 x 900`，会务端为全局顶栏、`202px` 侧栏、`328px` 审核队列和弹性详情区。
- 宽度收缩：低于 `1024px` 时，桌面端队列成为可展开列表，审核详情占主列；不保留横向三栏滚动。
- 安全区：移动端顶部/底部采用 `env(safe-area-inset-top)` 与 `env(safe-area-inset-bottom)`；底部内容额外留出导航高度。
- 不可妥协项：当地时间和对照时区、状态文字、冲突理由、审批/采纳/忽略动作必须同时可见；长标题可换行，不截断时间和状态。

## 8. 交付与技术约束

- 设计证据：上述 Figma 四帧为当前 T3 V3.1 评审依据；已将三个新版移动端帧的底部导航首项由“发现”同步为“会议”，未改变视觉样式或布局；旧版帧保留，不再作为实现基线。
- 实现方式：标准 HTML/CSS、CSS Grid/Flex、Lucide 图标、本地模拟数据即可实现；无图像、视频或第三方视觉资源依赖。
- 动效：仅允许 `160ms` 的按钮/状态淡入反馈；不能以动效隐去冲突、审核或日程变更结果。
- 可访问性：状态使用颜色和文字双重表达；保留焦点样式；触控目标不小于 `44px`。
- 已接受偏差：由于当前环境无 Stitch 接口，本版使用 Figma 生成；竞赛 Demo 凭证为文本码，AI 为可解释的本地规则模拟。
- 实现边界：关键帧冻结视觉语言、信息层级与组件样式，不替代已确认的 T1 功能范围或 T2 状态转移；后续页面实现须在此风格基线上补齐所有 P0 功能、异常和反馈状态。
